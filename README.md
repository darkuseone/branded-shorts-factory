# branded-shorts-factory

Один готовый JSON → один готовый вертикальный YouTube Shorts (1080×1920).

Сценарий пишется отдельно (в чате с Claude) и кладётся в репозиторий. Дальше всё
делает пайплайн: ищет материалы, генерирует аватар и озвучку, проверяет визуал
двумя уровнями контроля, монтирует через HyperFrames и отдаёт `.mp4`.

```
JSON → валидация → голос (ElevenLabs v3) → аватар (HeyGen Avatar 5)
     → мультипоисковые стоки → эскалация в Magnific → QA L1 (логика)
     → QA L2 (Grok Vision) → таймлайн → HyperFrames lint/check/render → MP4
```

---

## Как это запускается

**Только через GitHub Actions.** Локальная машина не нужна и не поддерживается:
весь рендер, все ключи и все артефакты живут в репозитории. Сценарий пишется в
чате, кладётся в `jobs/` и пушится — дальше всё происходит на раннере.

### Обычный путь

1. Положить сценарий `jobs/<id>.json` и клип аватара `jobs/<id>/avatar.mp4`.
2. Запушить. Workflow **Render Short** стартует сам.
3. Готовый `.mp4` и отчёт — в артефактах запуска. Итог (QA, потраченные токены
   Magnific, предупреждения) виден прямо в Summary.

Запустить вручную: Actions → **Render Short** → Run workflow, указать путь к
JSON. Явно указанный путь всегда важнее того, что пайплайн вывел бы из пуша.

Если сценарий в `jobs/` один, его не надо называть — он выбирается сам. Правила
выбора и их тесты: [`scripts/pick_scenario.py`](scripts/pick_scenario.py),
[`tests/test_pick_scenario.py`](tests/test_pick_scenario.py).

### Аватар

`Render Short` рендерит с готовым клипом аватара и **не ходит в HeyGen**. Клип
делается один раз через HeyGen MCP в чате и коммитится как
`jobs/<id>/avatar.mp4` — настоящими байтами, не указателем LFS. Один рендер
аватара на ролик; крупный план получается кропом, а не вторым рендером.

Workflow **Build Short** — единственный, кто зовёт HeyGen сам; он нужен только
когда готового клипа нет, и требует `HEYGEN_API_KEY`.

### Секреты репозитория

| Секрет | Зачем | Без него |
| --- | --- | --- |
| `ELEVENLABS_API_KEY` | озвучка + звуковой дизайн | нет голоса, субтитры по оценке |
| `MAGNIFIC_API_KEY` | премиальный визуал, стоковая база, иконки | только бесплатные стоки и рисованные глифы |
| `PEXELS_API_KEY`, `PIXABAY_API_KEY` | основные бесплатные стоки | остаются бесключевые источники |
| `GROK_API_KEY` | жёсткая проверка зрением + резервная генерация | слоты уходят на ручную проверку |
| `POND5_API_KEY` | бесплатная часть Pond5 | источник пропускается |
| `HEYGEN_API_KEY` | только для **Build Short** | `Render Short` работает и без него |

Переменные (Settings → Variables): `MAGNIFIC_TOKEN_BUDGET` (по умолчанию 40),
`MAGNIFIC_TOKEN_RESERVE` (10).

### Что стоит денег, а что нет

Лестница материала идёт снизу вверх и останавливается, как только слот закрыт:
локальный кэш → NASA и архивы → бесплатные стоки → **стоковая база Magnific**
(бесплатно, 100 скачиваний в сутки) → **безлимитные модели Magnific**
(генерация без списания) → метрируемые модели (кредиты, только по бюджету).

Суточная квота считается в `.state/magnific-downloads.json` и коммитится: за
день бывает несколько запусков, и они делят одну квоту тарифа. Иконки компаний
оседают в `assets/icons/` — второй ролик про ту же компанию не платит ничего.

## Разработка

Тесты и линт гоняет CI на каждый пуш. Локально они нужны только если вы правите
код:

```bash
pip install pytest ruff pydantic PyYAML
PYTHONPATH=src python -m pytest
ruff check src tests scripts && ruff format --check src tests scripts

# Проверить сценарий, не запуская сборку
PYTHONPATH=src python -m shorts_factory validate jobs/<id>.json
```

Сборку локально гонять не нужно: ключей на машине нет, а `Render Short` делает
то же самое за 15 минут и оставляет артефакт.

## Что кладёт пользователь

| Папка | Что там | Кто наполняет |
| --- | --- | --- |
| `jobs/` | сценарии `.json` | вы |
| `assets/music/` | 5 музыкальных треков | вы |
| `assets/sfx/` | 20–40 коротких звуков (переходы, удары, подъёмы) | вы |
| `assets/memes/` | 20–40 мемов | вы |
| `brand/brandbook.json` | брендбук | появится позже |
| `assets/catalogs/mixkit.json` | ручной каталог Mixkit | по мере находок |

**Файлы нужно коммитить в репозиторий.** GitHub Actions собирает ролик из
свежего клона: то, что лежит только на вашем диске, до сборки не доедет.

## Формат сценария

Полное описание полей — [`docs/JSON_SPEC.md`](docs/JSON_SPEC.md), машинная схема —
[`schema/short.schema.json`](schema/short.schema.json), рабочий пример —
[`examples/venus-hell.json`](examples/venus-hell.json).

Коротко: `id`, `title`, `duration_target`, `hook`, `script[]`, `voice_settings`,
`avatar`, `visuals[]`, `music`, `audio_fx[]`, `captions`, `brand_elements`,
`cta`, `memes`, `constraints`.

Валидатор собирает **все** проблемы за один проход и адресует их путём в JSON
(`visuals[3].start`), а не падает на первой. Кроме ошибок он предупреждает о том,
что технически валидно, но плохо смотрится: провалы на визуальной дорожке,
слишком длинные предложения, вялый или захлёбывающийся темп речи, `stability`
вне окна 40–55.

## Как принимаются решения

### Поиск: несколько ключей, все источники сразу

Один слот `visuals[]` разворачивается в 3–6 запросов: основной, авторские
синонимы, модификаторы под тип кадра (`motion graphics animation`,
`data visualization animation`) и существительные из закадрового текста именно
этого момента. Все запросы уходят параллельно во все доступные источники —
сетка `провайдер × запрос` в пуле потоков. Результаты объединяются, дубликаты
схлопываются (найденность несколькими запросами — сильный сигнал релевантности)
и ранжируются по четырём осям: релевантность, качество, пригодность к 9:16 и
приоритет источника.

Русские запросы автоматически переводятся по встроенному глоссарию — стоковые
API англоязычные. Если слово перевести не удалось, будет предупреждение, а не
тихий мусор в выдаче.

### Расход токенов Magnific

Порядок жёсткий, дешёвое всегда раньше дорогого:

1. **Бесплатные стоки.** Если лучший результат ≥ 0.80 — берём, ничего не тратим.
2. **Библиотека Magnific** (входит в подписку, 0 токенов).
3. **Безлимитные модели Magnific** (0 токенов).
4. **Платные модели** — только если всё выше не сработало, и только в рамках
   бюджета: резерв под hero-кадры, лимит на один слот, общий потолок на прогон.
5. **Grok Imagine** — резерв, когда Magnific недоступен.

Типы `motion_graphics` и `infographic` эскалируются раньше остальных: свободные
стоки в них объективно слабы. Каждая трата пишется в леджер и попадает в отчёт —
на вопрос «почему прогон съел 12 токенов» всегда есть ответ строкой.

### Двухуровневая проверка

**Уровень 1 — нативный (бесплатный, мгновенный).** Сверяет метаданные
материала с текстом озвучки: лексическое пересечение, доменный конфликт
(в скрипте космос, а в кадре банка сока — отклоняем), `must_include` /
`must_avoid`, разрешение и пропорции.

**Уровень 2 — Grok Vision (строгий).** Из клипа вырезаются кейфреймы и уходят в
модель зрения с жёстким промптом: соответствие теме, посторонние объекты,
качество, уместность в премиальном ролике. Ответ — `pass` / `replace` /
`manual`.

Провал уровня 1 не пускает материал на уровень 2. `replace` отправляет слот к
следующему кандидату, `manual` — в отчёт для человека. Недоступное зрение
никогда не превращается в тихий пропуск: слот помечается на ручную проверку.

### Звук

Озвучка синтезируется посегментно; где доступен timestamps-эндпоинт, берутся
реальные тайминги слов — субтитры-караоке попадают в такт, а не «примерно».
Массив `audio_fx` даёт переходы, удары и подъёмы; если он пуст, набор
предлагается автоматически по монтажным склейкам.

Сами звуки берутся **сначала из вашего банка** `assets/sfx/` — по типу эффекта,
с учётом синонимов (`boom-…` найдётся по запросу `impact`) и с чередованием,
если под тип подходит несколько файлов. Генерация через ElevenLabs включается
только там, где в банке ничего не нашлось; в отчёте у каждого эффекта видно
`source`: `library` или `elevenlabs`. Закроете банком все используемые типы —
расход на звук будет нулевой, и эта дорожка заработает вообще без ключей.

Финальный микс собирается FFmpeg: настоящий сайдчейн-даккинг музыки под голос,
фейды, лимитер и нормализация громкости.

### Рендер

Только HyperFrames: `lint → check → render` (в Actions — с `--docker`).
Композиция — самодостаточный HTML-проект: медиа скопировано в `media/`,
относительные пути, ноль внешних запросов. Тайминг элементов задан
абсолютными CSS-кейфреймами в процентах от длительности, поэтому картинка
детерминирована при любой перемотке рендерера.
