# Инвентаризация существующего кода (ШАГ 1 плана миграции, §24 ТЗ)

Составлено до написания нового кода. Цель — зафиксировать, что уже работает,
что оборачивается адаптером, а что выбрасывается.

Состояние на момент инвентаризации: пакет `src/shorts_factory/`, 129 тестов,
ruff чистый, PR #1. Пайплайн умеет: один сценарий JSON → поиск стоков → QA →
композиция HyperFrames → MP4.

## 2. Чего нет вообще (новые стадии, §24 ШАГ 4)

s00 topic_scout, s01 research, s02 script writer (сейчас сценарий пишет человек
в чате), s06 gapfill, s07 meme_director (есть только подстановка по тегу),
s08 infographic engine, s12 qc gate, s13 publish. Плюс ядро: `state`, `cache`,
`retry`, `costs.jsonl`, деградационная лестница.

Существующий проект решает примерно стадии 04, 05 (частично), 09, 10, 11 —
то есть середину конвейера. Начало (тема → факты → сценарий → раскадровка) и
конец (QC → публикация) отсутствуют.

## 3. Что изменилось во внешних интерфейсах с момента написания старого кода

Раньше REST-поверхности Magnific и HeyGen приходилось угадывать, и код был
написан защитно. Теперь оба доступны как MCP-инструменты с документированными
контрактами:

- **Magnific**: `stock_search` / `stock_download` (сток по подписке),
  `images_generate`, `video_generate`, `simulate_cost` (предварительный расчёт
  стоимости — прямо закрывает требование §19 о контроле кредитов),
  `account_balance`, `creations_wait`.
- **HeyGen**: `create_video_from_avatar`, `get_video`, `list_avatar_looks`,
  `list_voices`, `search_audio_sounds`.

Это меняет решение по `generative/magnific.py`: вместо угаданных эндпоинтов —
клиент с двумя транспортами (MCP при запуске из Claude Code, REST в Actions),
как §14.2 требует для HeyGen. Интерфейс один, транспорт выбирается по среде.

## 4. Где хранятся ключи

`os.environ`, читаются один раз в `config.Credentials.from_env()`. В GitHub
Actions — repository secrets, прокидываются в `env:` шага. В логи не попадают.
Это соответствует §0.8 и §23.1 п.6, менять не нужно.

## 5. Что работает хорошо и трогать не нужно

1. **Генератор композиции HyperFrames.** Самодостаточный HTML, медиа копируется
   локально, ноль внешних запросов, абсолютные CSS-кейфреймы → детерминированный
   рендер при любой перемотке. Это ровно то, чего требует §16.1.
2. **Мультиключевой параллельный поиск.** Сетка «провайдер × запрос» в пуле
   потоков — готовая основа для §9.3 с пулом на 8 воркеров.
3. **Доменный конфликт в L0.** Дешёвая детерминированная проверка «показываем
   не то» — именно то, что §10.1 требует делать без модели.
4. **Банк звуков с ротацией.** Закрывает §3.2 и §19 (нулевой расход на SFX).
5. **Валидатор сценария, собирающий все ошибки за проход.** Готовая площадка для
   правил §7.3 и §7.5.

## 6. Порядок работ

Следуем §23.2. Отклонение от буквы ТЗ, принятое осознанно:

> ТЗ показывает `src/core/...`, `src/pipeline/...` без пакета. Реализуем как
> `src/redshift/{core,clients,pipeline,render,prompts}` — настоящий Python-пакет.
> Причина: без пакета импорты между стадиями требуют возни с `sys.path`, а
> тесты и `python -m` перестают работать одинаково локально и в Actions.
> Структура каталогов и имена файлов сохранены один в один.

Старый пакет `shorts_factory` остаётся рабочим на время миграции (§24, правило
отката) и удаляется, когда новый конвейер даст ролик не хуже на той же теме
(§24 ШАГ 5).
