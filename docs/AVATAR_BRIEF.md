# Аватар: что генерировать и с какими настройками

Аватар делается в чате через HeyGen MCP, кладётся в `jobs/<id>/avatar.mp4` и
коммитится. Actions его не генерирует — там нет ключа HeyGen и не должно быть.

## Единственный разрешённый аватар

```
avatar_id: 54172d7a5b2946ed8a592dee955fb0c7   (Avatar 5)
```

Другие использовать нельзя. В сценарии до 11 августа стоял
`37fa8301e2dd46b2a8d11d4b766a6a50` — чужой; отсюда и лицо, которого клиент не
узнавал.

## Эталоны

Ролики, которые клиент называет годными, — из этого же аватара:

```
ba08579adcf44561b705465fce420112
861e4378a245410bbfe816060f00e340
```

Перед генерацией нового ролика имеет смысл вытащить их настройки
(`get_video`) и повторить: голос, скорость, эмоцию, фон, кадрирование.

## Голос идёт вместе с видео

HeyGen отдаёт клип, в котором **уже есть голос клиента и липсинк**. Именно он
и должен звучать в ролике: озвучка, синтезированная отдельно и положенная
поверх, не совпадает с губами — это ровно тот дефект, который был виден.

В сценарии за это отвечает:

```json
"voice": { "source": "avatar" }
```

При таком значении ElevenLabs не вызывается вообще. Дорожка достаётся из
`avatar.mp4`, а границы сегментов находятся по паузам в самой записи
(`voice/alignment.py`), поэтому субтитры и длины планов попадают в речь.

ElevenLabs остаётся для звукового дизайна (SFX) — это другая задача.

## Подача

- **Больше эмоции**, живее — монотонное чтение клиент называет главным
  недостатком предыдущей версии.
- **Без улыбки.** Улыбка открывает зубы и растягивает щёки; клиенту это не
  нравится. Нейтрально-серьёзная подача, интонация за счёт темпа и ударений, а
  не мимики.
- Стиль ролика в целом — **minimal tech**.

## После генерации

1. Скачать mp4 (со звуком, не «silent»).
2. Положить в `jobs/<id>/avatar.mp4`, закоммитить.
3. Проверить, что дорожка на месте: `ffprobe` должен показать `audio`.
4. Запускать Render Short.
