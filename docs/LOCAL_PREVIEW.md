# Смотреть кадры локально, не дожидаясь Actions

Прогон в Actions — полтора-два часа. Два самых дорогих дефекта в этом проекте
(субтитры в неправильном таймбейсе и без слоя) прожили несколько прогонов
именно потому, что каждая проверка стоила два часа, а в логе оба выглядели
как успех: композиция собрана, lint зелёный, mp4 записан. Увидеть их можно
было только глазами — на кадре.

Всё, что для этого нужно, ставится и работает прямо в репозитории.

## Инструменты

```bash
npx skills add heygen-com/hyperframes   # документация: анимация, контракт, CLI
npx hyperframes lint    <dir>           # быстрая структурная проверка
npx hyperframes check   <dir>           # + runtime, layout, motion, contrast
npx hyperframes snapshot <dir> --at 1.2,9.2,32.5 --no-end -o ../snaps
```

`snapshot` кладёт PNG по кадрам и `contact-sheet.jpg` — сетку из них. Сетку
достаточно открыть, чтобы за секунду увидеть то, чего не покажет ни один тест.

## Что смотреть в `check`

Строка **Contrast** — самый дешёвый сигнал о пропаже текста. Когда субтитры
были невидимы, там стояло `0/0 text checks`: проверять было нечего, текста на
экране не существовало. Сейчас `6/6 pass`. Ноль в этой строке при непустом
сценарии — всегда дефект, даже если всё остальное зелёное.

## Композиция без ключей

Стоковым API нужны ключи, которых на машине разработчика нет, но гейтам
безразлично, что за клип лежит за кадром — им важна разметка. Собрать
представительную композицию можно из сгенерированных ffmpeg заглушек: реальные
карточки, реальные субтитры, цветные прямоугольники вместо футажей. Тогда
`lint`, `check` и `snapshot` проверяют ровно то, что поедет в Actions.

## Проба вместо догадки

Когда непонятно, как ведёт себя рантайм, — быстрее всего собрать композицию из
двух элементов, отличающихся ровно одним свойством, и снять кадр. Так был
установлен таймбейс: два одинаковых клипа, у одного кадры записаны в локальном
времени, у другого в абсолютном; на пятой секунде виден только первый. Это
надёжнее любого рассуждения о том, что «должен» делать сикер.
